LLM via API

OpenRouter is a service that provides access to many LLMs through a web app and an API. Some are paid, others are free up to a certain number of queries. Follow the OpenRouter guide (under Tools on the course website) to create an account and an API key with a $0 limit, so you use only the free models, and to set the OPENROUTER_API_KEY environment variable in your terminal and in R. Run the check at the end of the guide before you start.

  1. Click on the “Models” tab to see the available models. How many total models are there? How many are free to use?1
  1. Search for and then click on a model called “Google: Gemma 4 31B (free)” and read the documentation page. What are its capabilities?

Everyone using the free version of Gemma 4 31B shares it, and when it’s busy, a request fails with HTTP 429 Too Many Requests. If that happens, wait a minute and try again. If it keeps happening, use another free model that can call tools, such as nvidia/nemotron-3.5-super-vl:free, in place of Gemma for the rest of this problem set. Its answers will be worded differently from the examples in the solutions, and it may print its reasoning in a <thinking> block before each answer.

At the bottom of the page, it shows example API calls in several programming languages. Copy the curl example and paste it into a JSON file in Positron (create a new file and give it a .json file extension). You can select all of the contents of that file, right click it, and select “Format Document” to make it more readable.

(Optional but cool): Most models have a standard set of other parameters that you can send that will determine how the model generates its text response. You can explore these by reading ?chat_openrouter(). Max tokens is the maximum length of the response (in tokens, where 1 token is roughly 4 characters of text). Temperature controls how “creative” the model is allowed to be: a temperature of 0 means it will always pick the most likely next token, while values closer to 2 will make it more likely to pick less probable tokens, resulting in more varied and creative responses. You pass these parameters as a named list to the params argument of chat_openrouter().

  1. Create a new chat object called or3 that uses the “google/gemma-4-31b-it:free” model but sets the temperature parameter to 2 and the max_tokens parameter to 500. Use or3 to send the prompt “Describe new types of punctuation and the emotions they evoke”. Initialize or3 again and send the same prompt several times to get a sense of how the responses vary. Change the temperature of or3 to 0 and send the same query several times. Write your observations below.

Tool Calls

These problems use chat_openrouter() with the same free model as the last two sections, google/gemma-4-31b-it:free, which supports tools. If Gemma is busy, select another free model to use such as nvidia/nemotron-3.5-super-vl:free. If you’ve started a new R session, check that your key is set (see “Check that it worked” in the OpenRouter guide) and load ellmer.

In lecture we offered the model a function that predicts a penguin’s body mass from its flipper length:

predict_mass <- function(flipper) {
  new_penguin <- tibble(flipper_length_mm = flipper)
  predict(penguin_model, new_penguin)
}

mass_tool <- tool(
  predict_mass,
  name = "predict_mass",
  description = "Predicts a penguin's body mass, in grams, from its flipper length.",
  arguments = list(
    flipper = type_number("Flipper length, in mm.")
  )
)
