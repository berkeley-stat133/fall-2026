Concept Acquisition

  1. Literate programming interleaves natural-language explanation with source code, so a single document produces both the report and the analysis behind it.
  2. A Quarto document keeps prose, code, and metadata in separate regions of one file.
  3. Source is kept separate from output: one .qmd can be rendered to many formats (HTML, PDF, Word, slides).
  4. Positron brings the file system, shell, R/Python, git, and Quarto together in one environment.

Tool Acquisition

  1. quarto render and quarto preview at the command line.
  2. Markdown syntax for headers, italics, bold, ordered and unordered lists, footnotes, and images.
  3. Code cell syntax: opening and closing fences, language, and #| cell options (eval, echo, message, warning, figure size), plus displaying tables.
  4. YAML metadata: opening and closing fences and common format values.
  5. The Quarto Guide and Quarto Reference as documentation for finding new options.

quarto render

Runs all of the code in a .qmd file, formats the text, and renders into a formatted document.

quarto render mydoc.qmd

quarto preview

Renders a .qmd file and opens a live preview that automatically re-renders and refreshes whenever the file is saved.

quarto preview mydoc.qmd

Guess the Metaphor

A Quarto doc is like a spellbook: the incantations (code) are written out next to the explanations of what they do and why (prose), and nothing happens until you cast it.

When you render, every spell runs in order and its effects (tables, figures, results) appear on the page, so anyone with the book can cast the same spells and get the same results.
