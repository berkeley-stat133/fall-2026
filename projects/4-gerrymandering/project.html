Project: Gerrymandering

Very soon Californians will go to the polls to vote for their representative to the United States Congress. This election will determine whether the Republicans retain control of the House of Representatives. This is the first election held using district maps that are explicitly partisan. One year ago, Californians passed Proposition 50, which adopted a congressional district map drawn by the state legislature (bill AB 604). The purpose of this bill was to increase the partisan advantage of Democrats as a counterweight to a similar district map that was passed by the state of Texas to advantage the Republicans.

Your general research question for this project is:

Will the adoption of the new district map lead to an increase in partisan advantage relative to 2024? If so, by how much?

As always, you will be invited by email to a template repo corresponding to this project. This time, project.qmd is set to format: dashboard, the format from the Dashboards lecture. Each part below is a page of your dashboard. How you lay out each page is up to you, but each should show your results as explanatory displays (plots, tables, value boxes, or a few sentences) along with the code that produced them. The comment at the top of the template’s project.qmd has some tips on how to set this up.

Your dashboard opens on its Results page (Part 6), because that is where a reader starts, but you’ll build that page last: work through the parts in order.

In the assignment below, “On this page” describes what each page of your dashboard should show. The questions are there to prompt you to fully explore each phase of the analysis to be ready to answer questions about it during the Project Studio.

Context

  • California Statewide Special Election (https://www.sos.ca.gov/elections/prior-elections/statewide-election-results/statewide-special-nov-4-2025): official website for the election from the CA Secretary of State.
  • Statewide Database Precinct Data (https://statewidedatabase.org/d20/g24.html): source of precinct-level data from the 2024 General Election.
  • 2024 Election Geographic Data (https://statewidedatabase.org/d20/g24_geo_conv.html): source of shapefiles for precinct maps from 2024 General Election.
  • Proposed Congressional Map (https://aelc.assembly.ca.gov/proposed-congressional-map): source of shapefiles for district map proposed in AB 604.

Data

The template’s data/ folder holds:

  1. state_g24_sov_data_by_g24_srprec.csv: Voting results (Statement of Vote) for the 2024 general election by registration precinct (SR precinct), from the Statewide Database (source: https://statewidedatabase.org/d20/g24.html). Its columns are described in the Statewide Database’s codebooks (https://statewidedatabase.org/info/codebooks.html).
  2. g24-results-by-district.xlsx: Voting results at the district level, broken down by county.
  3. g24-candidates-by-district.csv: Names of candidates running in each district race.

In Parts 5 and 6 you’ll download more files and add them to data/ yourself, unzipping any shapefiles into a subdirectory called data/shapefiles. Many of these files are too large for GitHub, so the template’s .gitignore keeps git from committing anything in data/ beyond the three files above. Keep every download inside data/: a file saved anywhere else would be committed. If you save a cleaned version of a data set, which is good practice, write it to data/clean/; that folder is committed.

Part 5: Re-running the 2024 Election

Calculate what the election results would have been had the 2024 election been run using the district map proposed in AB 604. There are two approaches that can be taken. Both start from the SR precinct data you cleaned in Part 2: SR precincts are always geographical, so their votes can be placed on a map.

The data files listed below are not in the template repo; you’ll be downloading them directly. Put csv files in data/ and unzip any shapefiles into data/shapefiles/, not anywhere else in your repo: inside data/, git ignores them, and some are far too large for GitHub (the SR precinct shapefile is over 300 MB). The AB 604 zip unpacks into an AB604/ folder, so its shapefile is data/shapefiles/AB604/AB604.shp, alongside a __MACOSX/ folder you can delete. Its districts are in a Web Mercator projection, so transform them with st_transform(crs = 3310) before combining them with other layers. Some of this code is slow to run, so the template marks this part’s code cell with cache: true: it reruns only when you change it or the Part 2 cleaning it builds on.

Of these two approaches, Approach A is slightly more direct but induces a bit more error than Approach B. You can choose one to pursue. If you end up doing both, I’d be very interested in an analysis that compares the results. Please email me directly if you do this to share your work.

Approach A: Area-weighted Interpolation

Premise: if we assume the voters are spread evenly across their precincts, we can allocate a precinct’s votes to a congressional district in proportion to the percentage of the area of that precinct that is in the district. Along with your clean SR precinct data, you will need two files:

  1. SR Precinct Shapefiles: Shapefiles for the SR precincts (source: https://statewidedatabase.org/d20/g24_geo_conv.html).
  2. Proposed Congressional Map: source of shapefiles for district map proposed in AB 604 (source: https://aelc.assembly.ca.gov/proposed-congressional-map).

General approach:

  1. Join the geometries from the shapefile to your clean SR precinct data.
  2. Load geometries of the proposed congressional map.
  3. Ensure both geometries are valid and use the same projection (I recommend st_transform(crs = 3310)).
  4. Use area-weighted interpolation to populate the vote counts of each district in the proposed map.

Note: the people at the Statewide Database are working to correct some errors in the geometries of the SR precincts. sf can do a quick job of it using the following:

sr_shp <- sr_shp |>
  st_transform(3310) |>          # switch to equal area projection first
  st_set_precision(1) |>         # snap points to 1 m grid
  st_make_valid() |>             # fix self-intersections/bow-ties
  st_collection_extract("POLYGON")

Approach B: Proportional Allocation

Premise: we can improve on the uniform distribution assumption by working with a smaller geographic unit, census blocks. While we don’t know the number of votes for each candidate at the census block level, we do know the proportion of registered voters at each census block. We can allocate the votes from the SR precincts across the blocks relative to the proportion of registered voters that live on that block.

Along with your clean SR precinct data, you will need two files:

  1. SR Precinct to Block Correspondence: Number of registered voters by (partial) block (source: https://statewidedatabase.org/d20/g24_geo_conv.html).
  2. Block membership in AB 604 districts: A list of the census block keys and their new congressional district as of AB 604 (source: https://aelc.assembly.ca.gov/proposed-congressional-map).

General approach:

  1. Working from the census block data, add SR voting data to each (fractional) block in proportion to the percentage of registered voters in the precinct that live on that block.
  2. Identify which new district each block is in.
  3. Tally up the votes for each new district.

Note: there are some census blocks that are split between multiple SR precincts. Accordingly, each row of the SR Precinct - Block correspondence file is actually a potential fractional block: most rows represent an entire block, but some represent the portion of a block that is in a particular precinct. BLKTOTREG is the total number of registered voters in the full block; SRTOTREG is the total number of registered voters in the SR precinct. PCTSRPREC is the percent of the total SR registrants that live on the fractional block. BLKREG is the number of registered voters on the fractional block.

On this page: how you estimated the 2024 votes in each of the new districts: the approach you chose and the assumption it rests on, the estimated votes for each party in each new district, and a check of whether your allocation kept every vote.
