Reading (and Writing) Data

Plain Text File

A file that stores only characters, so it can be opened and read by any text editor, by cat in the shell, or by readLines() in R.

Binary File

A file that stores raw bytes meant to be decoded by specific software. Opened as text, it looks like gibberish.

Every file is bytes on a disk. Only plaintext encodes characters you can read.

Binary Files: PDF and Excel

PDF (.pdf)

  • Describes a printed page: fonts, positions, images
  • Great for humans to read
  • Data inside a PDF table is hard to get back out

Excel (.xlsx)

  • A zipped bundle of files: cell values, formulas, formatting, multiple sheets
  • Requires Excel or a package like readxl to decode

Writing .txt

Each element of a character vector becomes one line.

card <- c("Golden Klaxons", "3000")

# base R
writeLines(card, "data/127-clean.txt")

# readr
write_lines(card, "data/127-clean.txt")

.md: Text Plus Markup

A Markdown file is a .txt file with markup: extra characters that tell a renderer how to display the text.

127.md
# Song of Summer

**Golden Klaxons**, card `127`

- Distance: *3000?* miles
- Source: index card

Song of Summer

Golden Klaxons, card 127

  • Distance: 3000? miles
  • Source: index card

.R

An R script is plain text containing R code.

read-cards.R
contents <- c()
notecard_files <- dir()

for (notecard_file in notecard_files) {
    notecard <- readLines(notecard_file)
    contents <- c(contents, notecard)
}

YAML

A plain text format for configuration and metadata built from key: value pairs. Indentation marks nesting and a leading - marks an item in a list.

The course website’s schedule is a YAML file:

CSV

A comma-separated values file stores tabular data with each row on a new line and each column delimited by a comma. A lingua franca for storing data frames in your file system.

Structure of a CSV

  • First line: column names (the header)
  • One row per line, columns separated by commas
  • Missing values written as NA

Writing CSVs

write.csv(penguins, "data/penguins.csv", row.names = FALSE)

write_csv(penguins, "data/penguins.csv")


Without row.names = FALSE, base R adds an unnamed column of row numbers to the file.

JSON

JavaScript Object Notation: a plain text format of nested objects ({"key": value}) and arrays ([a, b, c]). The most common format for data sent over the web.

cards.json
[
  {"id": 127, "song": "Golden Klaxons", "distance": "3000?"},
  {"id": 14,  "song": "Espresso",       "distance": "40"},
  {"id": 3,   "song": "Let It Go",      "distance": "1200"}
]

Reading and Writing JSON

An array of objects that share the same keys becomes a data frame.

library(jsonlite)
cards <- fromJSON("data/cards.json")
cards
   id           song distance
1 127 Golden Klaxons    3000?
2  14       Espresso       40
3   3      Let It Go     1200

Reading and Writing JSON

An array of objects that share the same keys becomes a data frame.

toJSON(cards[1, ], pretty = TRUE)
[
  {
    "id": 127,
    "song": "Golden Klaxons",
    "distance": "3000?"
  }
]

To write to a file: write_json(cards, "data/cards.json").

Writing JSON and YAML

  • A key-value pair: "key": "value" wrapped in { } (JSON); key: value (YAML)

  • A list of key-value pairs:

Writing JSON and YAML

  • A key-value pair: "key": "value" wrapped in { } (JSON); key: value (YAML)
  • Multiple pairs: separated by commas (JSON); one per line (YAML)
  • A list: items in [ ], separated by commas (JSON); indented items, each starting with - (YAML)
  • A list of key-value pairs:
playlist.json
{
  "name": "Study Mix",
  "owner": "Ana",
  "tags": ["lofi", "focus"]
}
playlist.yml
name: Study Mix
owner: Ana
tags:
  - lofi

Writing JSON and YAML

  • A key-value pair: "key": "value" wrapped in { } (JSON); key: value (YAML)
  • Multiple pairs: separated by commas (JSON); one per line (YAML)
  • A list: items in [ ], separated by commas (JSON); indented items, each starting with - (YAML)
  • A list of key-value pairs: { } objects inside [ ] (JSON); pairs indented under each - (YAML)
playlist.json
{
  "name": "Study Mix",
  "owner": "Ana",
  "tags": ["lofi", "focus"],
  "songs": [
    {"title": "Espresso", "artist": "Sabrina Carpenter"},
    {"title": "Let It Go", "artist": "Idina Menzel"}
  ]
}
playlist.yml
name: Study Mix
owner: Ana
tags:
  - lofi
  - focus
songs:
  - title: Espresso
    artist: Sabrina Carpenter
  - title: Let It Go
    artist: Idina Menzel

Reading and Writing: Summary

Format Base R Tidyverse and friends
.txt readLines() / writeLines() read_lines() / write_lines() (readr)
.csv read.csv() / write.csv() read_csv() / write_csv() (readr)
.yml read_yaml() / write_yaml() (yaml)
.json fromJSON() / write_json() (jsonlite)
.xlsx read_excel() (readxl) / write_xlsx() (writexl)

Readr

Why prefer readr?

  • Returns a tibble
  • Reports the column types it guessed
  • Consistent read_*() / write_*() naming
  • Faster on large files

Guess the Metaphor

Reading and writing data is like working the docks: cargo (data) arrives packed in containers (files). Some crates you can pry open by hand (plain text); others need special tools (binary). Reading unloads the cargo into town (R); writing packs it back up to ship out.
