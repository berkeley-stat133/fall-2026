Running a Plumber API from your session

  1. Move code into R script (e.g., stat133-api.R)
  2. Use plumber::plumb() to load the script
  3. Use pr_run() to start the API server
library(plumber)
stat133_api <- plumb("stat133-api.R")
pr_run(stat133_api,
       host = "0.0.0.0",
       port = 8080)

Connecting to the API

  • If your computer is the API server, you can access it at:
http://localhost:8080/greet?name=Andrew
  • For “production” use, deploy to a cloud service (e.g., Digital Ocean, AWS, Posit Connect, etc.)

The path of a request

http://localhost:8080/greet?name=Andrew
Part of the request What Plumber does with it
localhost:8080 reaches the server running in your R session
/greet picks the function tagged @get /greet
?name=Andrew calls it with name = "Andrew"
  • Query values always arrive as strings: ?year=2000 gives "2000". Convert with as.numeric().
  • The function returns list("Hello Andrew!"). The serializer turns it into the response, [["Hello Andrew!"]], labeled as JSON.
  • Every response has a status: 200 OK, 404 when no function matches the path, 405 when the path exists but for another method (a browser’s GET to a POST endpoint).

Serializer

Converts what an endpoint returns into the format of the response. Plumber returns JSON by default; a @serializer annotation changes the format.

  • Common serializers:
    • @serializer json (default)
    • @serializer png
    • @serializer jpeg
    • @serializer html
    • @serializer svg

Plot first, then serve

Put the plotting in an ordinary function at the top of the API file, next to the library() calls:

library(babynames)
library(dplyr)
library(ggplot2)

plot_name <- function(babyname) {
  babynames |>
    filter(name == babyname) |>
    group_by(year) |>
    summarize(n = sum(n), .groups = "drop") |>
    ggplot(aes(x = year, y = n)) +
    geom_line() +
    labs(title = paste("Popularity of", babyname, "over time"),
         x = "year", y = "Count") +
    theme_bw()
}

#* Plot the popularity of a name over time
#* @param babyname The name to plot
#* @get /plot
#* @serializer png
function(babyname = "Mary"){
  print(plot_name(babyname))
}

Let’s improve the clarity by returning an SVG (Scalable Vector Graphics) image instead of PNG.

#* Plot the popularity of a name over time
#* @param babyname The name to plot
#* @get /plot
#* @serializer svg
function(babyname = "Mary"){
  print(plot_name(babyname))
}

Guess the Metaphor

Building an API is stepping into the kitchen behind the bakery counter: each recipe is an endpoint, its card lists the ingredients (parameters), and the plating (serializer) decides how the dish goes out.

POST Requests

POST Request

An HTTP method, like GET, that sends data to a server to create or update a resource or to parameterize an operation. The data goes in the body of the request, not in the URL.

  • Commonly used for:
    • Submitting form data
    • Uploading files
    • Sending JSON payloads

A guestbook

POST is for requests that change the server. Our server will keep a guestbook in a CSV file.

library(readr)   # tibble() comes from dplyr, loaded at the top

write_csv(tibble(name = character(), message = character()),
          "guestbook.csv")

#* Sign the guestbook
#* @param name Your name
#* @param message Your message
#* @post /entry
function(name = "Anonymous", message = ""){
  write_csv(tibble(name = name, message = message),
            "guestbook.csv", append = TRUE)
  list(signed = name)
}

Reading the guestbook

#* Read the guestbook
#* @get /entries
function(){
  read_csv("guestbook.csv", col_types = "cc")
}
  • A GET only reads: it returns every row so far, as JSON.
  • col_types = "cc" reads both columns as text, so a name like 123 stays a name.
